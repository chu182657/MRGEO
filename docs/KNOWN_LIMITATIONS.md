# Known limitations and author actions

These observations come from the supplied code/data, not a full review of the final manuscript (which was not supplied with this batch).

1. **Empty queries:** every `data/samples.json` contains 1,000 records and all queries are empty, including the first 200. Fields are `sample_id`, `query`, `documents`; there is no target-source index or category label. Counts: 997 records have 5 documents, 2 have 4, and 1 has 3. Recover the actual experimental input if a different file was used. Do not manufacture replacement queries and describe them as historical inputs.
2. **Main procedure:** `run_generation.py` passes the whole sample to `build_prompt`, then directly records one generated answer. `methods.py:build_m2geo_prompt` places the five steps inside one prompt. This is different from five externally executed target-source transformations followed by source replacement and a separate answer generation call. Sequential ablation scripts exist separately and do not establish that the main run used that protocol.
3. **Sample selection:** the main DeepSeek script uses `samples[:200]`; the included data lacks stratification labels. This does not demonstrate stratified sampling with seed 2024. Preserve/recover actual selected query IDs and upstream mappings.
4. **Baseline provenance:** named advanced methods are implemented as local prompts (for example role simulation and multidimensional text analysis). Names alone do not establish a faithful implementation of a published baseline. Verify citations, implementations and any adaptations. No `Original` method is in the 14-method main list; ablation Raw is a different experiment.
5. **Failed scoring:** DeepSeek `judge_full.py` returns zeros on failure; `run_evaluation_full23.py` computes aggregate scores from those values. Contradiction inversion can produce a nonzero aggregate even on failed scoring. `evaluation_results_full23_200.csv` has 302 nonempty error fields out of 2,800 rows. Do not count failures as successful scores. Define and document validity and pairing rules before recomputing tables.
6. **Duplicates and mixed stages:** Gemini `evaluation_results_full23_gemini.csv` has 2,936 rows, 136 duplicate sample-method rows and 2,871 error-marked rows. GPT `evaluation_results_full23_chatanywhere_FINAL_slow.csv` has 2,727 rows and 53 duplicate sample-method rows. Filenames such as FINAL/SAFE do not establish validity. See `audit/score_inventory.json`. No final score file was silently chosen.
7. **Variant attribution:** the Claude folder contains `modified_111.csv` and its executable evaluator uses a different metric schema. Folder location is insufficient proof of engine/Judge attribution. Verify logs and run manifests before pooling results.
8. **Embedded plot values:** supplied figure scripts contain literal scores/W/CI/p-values; the CI scripts explicitly state query-level verification is pending. The plot scripts do not perform bootstrap or Holm correction themselves. Rendering them is not statistical reproduction.
9. **Missing reproduction inputs:** source/target metadata, a validated historical environment lock, run manifests and a verified paper-to-result mapping remain unresolved. Full leave-one-out/order result files were not found among the supplied output snapshots; scripts alone do not establish reported outcomes.
10. **Availability and credentials:** historical model routes may no longer work. API-backed experiments were not run. Revoke/rotate credentials present in the original uploads; only environment lookups remain in the release code.

Packaging intentionally preserves these scientific limitations rather than inventing a corrected history. A scientifically final release needs the authors' actual matching inputs/implementation or transparently documented new experiments and a consistent manuscript revision.
